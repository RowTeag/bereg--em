# SMM Panel

Панель создаёт готовые посты через OpenAI и позволяет отредактировать их перед публикацией.

## Вход и роли

При первом запуске панель создаёт локальную учётную запись владельца. Начальные данные входа сохраняются с правами `0600` в `.private/panel-access.txt`; пароли остальных сотрудников показываются только один раз при создании или сбросе.

- Суперадминистратор видит все разделы, подключения, обращения и управляет аккаунтами команды.
- Администратор работает с контентом, аналитикой, обращениями и Telegram-операторами, но не управляет аккаунтами панели и подключениями владельца.
- Оператор видит только клиентов, закреплённых за связанным Telegram-оператором, и может отвечать им или закрывать обращения.

Сеанс действует 12 часов. Отключение аккаунта или сброс пароля завершает его активные сеансы. Для изменяющих запросов используется проверка источника и CSRF-токен.

## Запуск

1. Скопируйте `.env.example` в `.env`.
2. Добавьте в `.env` свой `OPENAI_API_KEY`.
3. Выполните `npm install` и `npm start`.
4. Откройте `http://localhost:3000`.

API-ключ хранится только на сервере и не отправляется в браузер. Без ключа генератор покажет понятное сообщение о необходимости настройки.

## Реальная публикация в Facebook

1. Создайте приложение в Meta for Developers и добавьте вариант использования для управления страницей.
2. Получите Page Access Token с правами `pages_show_list`, `pages_read_engagement` и `pages_manage_posts` (для пользователей приложения вне ролей разработчика потребуется App Review).
3. Для Facebook откройте в панели «Настройки», укажите Meta App ID и Meta App Secret, добавьте показанный OAuth Redirect URI в настройках Meta-приложения и нажмите «Подключить через Facebook». Панель обменяет вход на долгоживущий токен страницы, сохранит его в `.private/facebook-oauth.json` с правами `0600` и будет обновлять доступ автоматически. Значения `FACEBOOK_PAGE_ID` и `FACEBOOK_PAGE_ACCESS_TOKEN` в `.env` остаются резервным способом подключения.
4. Перезапустите сервер. Над редактором должно появиться имя подключённой страницы.

Токен используется только сервером. Если Meta отклонит запрос, запись получит статус «ошибка», а интерфейс покажет реальное сообщение API вместо ложного статуса публикации.

## Бесплатная генерация через Ollama

1. Установите Ollama: https://ollama.com/download
2. Выполните `ollama pull qwen2.5:1.5b`.
3. Оставьте Ollama запущенным и перезапустите SMM Panel.

Локальная модель не требует API-ключа и не расходует платные кредиты. Если OpenAI недоступен из-за отсутствия кредитов, приложение автоматически переключается на Ollama.

По умолчанию используется `AI_PROVIDER=ollama`: темы и тексты не отправляются во внешний API. Чтобы вручную вернуть OpenAI, установите `AI_PROVIDER=openai` в `.env`.

Видео по умолчанию создаётся через HeyGen Avatar IV (`VIDEO_RENDER_MODE=heygen`): персонаж говорит по-русски, двигает губами, головой и руками. Добавьте `HEYGEN_API_KEY` в `.env`. При первом ролике приложение один раз создаст Photo Avatar из локального изображения и сохранит его ID в `generated/heygen-avatar.json`; создание аватара тарифицируется отдельно. Для бесплатной локальной синхронизации губ установите `VIDEO_RENDER_MODE=quality`; SadTalker на CPU значительно медленнее. `VIDEO_RENDER_MODE=fast` оставлен как моментальный статичный режим.

### Публикация в YouTube

Откройте «YouTube · публикация» и подключите канал. Для ранее подключённого канала обновите доступ: загрузка требует OAuth scope `youtube.upload`. Используются существующие `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET` и `YOUTUBE_REDIRECT_URI`.

Выберите видео до 200 МБ (MP4, MOV, AVI, WEBM, MPEG), укажите название, описание, видимость и детскую аудиторию. По умолчанию видео приватное. После успешной загрузки появится ссылка и фактическая видимость, возвращённая YouTube. При обрыве связи проверьте YouTube Studio перед повтором. Временный файл удаляется после завершения запроса.

Google может ограничивать видео из непроверенных API-проектов приватным режимом: https://developers.google.com/youtube/v3/docs/videos/insert

### Telegram: обратная связь

В BotFather создайте два разных бота. Добавьте их токены в `.env` как `TELEGRAM_CLIENT_BOT_TOKEN` и `TELEGRAM_OPERATOR_BOT_TOKEN`, затем перезапустите сервер. Боты используют getUpdates; webhook для этих ботов должен отсутствовать, другой экземпляр polling запускать нельзя.

Откройте на этом компьютере «Telegram · поддержка», создайте операторов и сохраните показанные личные пароли. Передайте каждому оператору его пароль самостоятельно. В операторском боте он вводит `/login пароль`; первый вход закрепляет Telegram-аккаунт за оператором. Пароль хранится только в виде scrypt-хеша, сообщение с паролем бот пытается удалить.

Новые клиенты назначаются доступному оператору с наименьшим числом активных клиентов. Повторные обращения сохраняют назначение. `/pause` останавливает новые назначения, `/online` возобновляет, `/clients` показывает активных клиентов. Ответьте на сообщение клиента штатной функцией Telegram «Ответить». `/close` ответом на сообщение закрывает обращение. Отключение оператора в панели освобождает его клиентов для переназначения.

Поддерживаются личные чаты и текст до 3500 символов. Очередь, назначения и история сохраняются в `.private/telegram/support.json`, вне публичной папки. Администрирование доступно только с localhost. Если операторов нет, сообщение ждёт в очереди. Ошибки доставки повторяются через минуту. При сетевом сбое после принятия сообщения Telegram возможна повторная доставка. Для непрерывной работы сервер должен оставаться запущенным.

При первом `/start` клиент выбирает русский, украинский, английский, венгерский или вьетнамский; сотрудник — русский, украинский, английский или венгерский. Telegram и Facebook/WhatsApp сообщения переводятся на язык сотрудника, а ответы — обратно на язык клиента. В CRM оригинал сообщения сохраняется рядом с переводом. Для автоматических переводов используется подключённый OpenAI API; если перевод недоступен, отправляется исходный текст. В генераторе маркетинговых постов есть отдельный выбор языка. Отдельный групповой маркетинговый бот поддерживает `/start` и `/language` в личном чате и отвечает на языке, выбранном сотрудником, либо на языке Telegram-профиля.

Проверки: `node --test test/telegram-support.test.js`.

### Клиенты и заявки с сайта

Раздел «Клиенты» доступен владельцу и администраторам. Анкета повторяет поля сайта Bereg Outsource Group. Телефоны нормализуются; повторное сохранение одного телефона обновляет карточку. Данные хранятся в `.private/crm/clients.json`. Существующие диалоги можно связать вручную; WhatsApp сопоставляется по номеру. Ссылки на приложения не проверяют наличие аккаунта и не отправляют сообщения.

Сайт сохраняет согласованные заявки в приватном Cloudflare KV. Сервер панели опрашивает защищённый API каждую минуту; из-за распространения данных KV возможна дополнительная задержка. Настройки подключения находятся в `.private/crm-site.json` (секрет не публиковать). Обработанные идентификаторы — `.private/crm/imported.json`. Кнопка «Обновить» запускает синхронизацию вручную. Во время выключения панели заявки остаются в KV. Устаревшие PDF из прежней версии сайта автоматически не импортируются.

### Сайт для демо CRM

Отдельная публичная страница предложения доступна по `/crm-offer`; журнал посещений и заявок владельца — `/crm-offer-admin` (вход тем же владельцем CRM). Имя и контакт попадают в журнал только после отправки формы. Посещения и нажатия учитываются только после согласия посетителя; IP-адреса не сохраняются, события и заявки удаляются через 90 дней. Заявка уходит через `TELEGRAM_OPERATOR_BOT_TOKEN` главному оператору с привязанным Telegram-аккаунтом. При необходимости задайте отдельный `TELEGRAM_SALES_CHAT_ID`; при ошибке отправки запись останется в журнале, где владелец сможет повторить доставку.
